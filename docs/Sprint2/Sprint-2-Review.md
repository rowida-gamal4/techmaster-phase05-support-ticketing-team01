# 4. Bugs Discovered
During Sprint 2, several issues were identified and corrected:
    - Ticket CreatedAt was initially being stored as DateTime.MinValue, which caused SLA calculations to immediately appear breached.
    - Ownership checks were strengthened so customers cannot operate on another customer's tickets.
    - Status transitions were restricted to valid workflow states rather than allowing arbitrary status changes.
These bugs helped strengthen the application's business-rule enforcement rather than being treated as only technical errors.

# 5. Architecture / Database Decisions
Sprint 2 continued the architectural decisions established in Sprint 1:
    - Clean Architecture remained the project structure.
    - CQRS + MediatR was used to separate each business operation into its own command/query handler.
    - Each conversation action was kept as a separate use case because customer comments, agent replies, and internal notes have different authorization rules.
    - ICurrentUserService remained the source of authenticated user identity rather than accepting user IDs from the request.
    - Ownership and assignment rules were enforced inside application handlers.
    - Ticket status transitions were treated as business rules rather than simple CRUD updates.
    - TicketStatusHistory was used to preserve workflow history.
    - TicketComment.Visibility distinguishes public communication from internal support communication.
    - SlaPolicy was introduced to calculate SLA targets from ticket category and priority.
    - SLA targets are calculated from server-side CreatedAt rather than supplied by the client.
    - Customer queries continue to exclude internal-only information.
